# Decisions & assumptions

Time is minutes into the 2 h box. Kickoff ran at about T=20.

| # | Time | Decision / assumption | Options considered | Why | Trade-off |
|---|------|-----------------------|--------------------|-----|-----------|
| 0 | 20 | **2 h box**: 20 min already spent, 90 min agent work, last 10 min for the human's final look + share. **One commit per slice straight to `main`**, no branch/PR flow. | 3 h box + PR per slice (CLAUDE.md §0/§9) | The real box is 2 h. The PR round-trip costs ~3 min per slice. | Less review ceremony; `make check` green is still required before every commit. CLAUDE.md said 3 h and PRs; the human gave one-time permission for the agent to update CLAUDE.md to match (red zone otherwise). |
| 1 | 20 | Input = JSON array (Must). CSV = Could. | JSON + CSV both Must | The brief accepts "JSON, CSV, or another"; one format proves the pipeline. | CSV users must convert first. |
| 2 | 20 | Required fields: `item_id`, `item_description`, `unit_of_measure`, `source_system`. Optional: `manufacturer`, `manufacturer_part_number`, `category`. A missing required field → R-001: **high** if `item_id` is missing, else **medium**. | All 7 fields required; only `item_id` required | A steward can't use a record without an id, a description, a UoM or a provenance. The other fields have their own checks. | Missing category is never flagged on its own. |
| 3 | 20 | Output = `{summary, candidates, parse_issues}`. Each candidate is a superset of the brief's example fields. | Bare list as in the brief | The summary and parse issues help the steward triage; the brief allows the shape to differ. | Consumers expecting a bare list must read `.candidates`. |
| 4 | 20 | The brief's `ai_or_heuristic_candidate` source is split into `heuristic` and `ai_assisted_candidate`. | Keep the combined label | The brief asks to make clear whether a finding came from a rule, a heuristic or AI. | None. |
| 5 | 20 | A repeated `item_id` (any system) → R-003: **high** if the other fields conflict, **medium** if the rows are identical copies. One candidate per row, cross-referencing the others. | Only within one source_system | The brief lists "duplicate item_id" and "conflicting source-system values" as edge cases. | Systems that legitimately share an id namespace will produce noise. |
| 6 | 20 | Same item across systems (H-002) = same canonical manufacturer (trim + casefold) + same canonical MPN on different rows. Description similarity is a Could. | Fuzzy description matching | MPN equality is high-precision and explainable. | Misses duplicates that lack an MPN. |
| 7 | 20 | Allowed UoM list lives in `config/rules.json`: EA, PC, SET, PR, BOX, PK, RL, KG, G, L, ML, M, MM, CM, IN, FT. A known alias (e.g. "each", "pcs", lowercase code) → **low** + `suggested_value`. Unknown → **medium**. | Free-form UoM | ISO/SAP-style short codes are the norm in item masters. | The list is a starting point and needs a steward's sign-off. |
| 8 | 20 | "Vague" description = no digit- or attribute-bearing token, and either ≤ 2 tokens or only generic nouns. | Length-only rule | "bearing" and "valve" (from the brief) fire; "SKF Bearing 6205 ZZ" does not. | Long but meaningless text can slip through. |
| 9 | 20 | Category mismatch: keyword → expected category map in `config/category_keywords.json`. Fires only when a keyword matches, the category is present and differs (casefolded). Confidence 0.70, matching the brief example. | Embedding / AI classification | Deterministic and explainable; the evidence names the keyword. | Limited vocabulary; English only. |
| 10 | 20 | Missing = `None`, `""`, whitespace, `"null"`, `"n/a"`, `"na"`, `"-"` (case-insensitive). Raw values are kept as evidence. | Only None/"" | The brief calls out blanks with whitespace and nulls. | A literal part called "NA" would read as missing (unlikely). |
| 11 | 20 | Numeric `item_id` is accepted as a string. A list/dict field value, or a non-object row, → parse_issue + R-001 high. | Reject the whole file | Bad rows must never crash the run (CLAUDE.md §7). | None. |
| 12 | 20 | `[]` → empty candidates, a message, exit 0. Unreadable file / invalid JSON / non-array top level → stderr error, exit 2. | Exit 1 on empty | Empty is a valid upload, not an error. | None. |
| 13 | 20 | Non-English / abbreviation-heavy text: Unicode-safe tokenising, no translation. The checks do not expand abbreviations; only the opt-in AI stub does (small list in `config/rules.json`, #20). | Abbreviation map inside the checks | Time box. | Known limitation; vague/category heuristics may miss these. |
| 14 | 20 | `finding_id` = first 12 hex characters of sha256(`rule_id|source_system|row_index|item_id`). | UUID4 | Must be stable across runs for the golden test + audit. | Changes if row order changes. |
| 15 | 20 | Severity and confidence are set only in `dq/scoring.py`, from config. Checks return the raw signal. | Each check sets its own | One policy place, easy to audit and tune. | One extra indirection. |
| 16 | 20 | `make` is assumed to run under Git Bash on Windows (it uses `mkdir -p`/`cat`). Fallback: `uv run python -m dq review …` in the README. | Rewrite the Makefile for cmd | The Makefile already exists and works in CI (Linux). | Windows users without Git Bash use the fallback. |
| 17 | 90 | H-003 assumes the three-category taxonomy in `config/category_keywords.json` (Mechanical, Electrical, Piping). Category comparison ignores case and a plural s. The ambiguous keyword "gauge" was removed. | Category equivalence map; synonyms per category | Red-team: any other taxonomy (e.g. "Instrumentation") produces a false positive on each keyword hit. | Stewards with a different taxonomy must edit the keyword file; findings are low severity and confidence 0.70. |
| 18 | 90 | A row with an unsupported field type (list, dict, bool, NaN) gets only the R-001 malformed_row finding; other checks skip it. | Keep running checks on the fields that parsed | Avoids reporting on values we could not trust, and keeps one finding per broken row. | Other real problems on that row appear only after the source owner resends it. |
| 19 | 90 | The CLI refuses `-o`/`--report` paths equal to the input file (exit 2). Deeply nested JSON is a clean exit 2 rather than a traceback. | Overwrite silently | Red-team: `-o` pointing at the input destroyed the source records, against "never modifies records". | None. |
| 20 | extra | A-001 (AI-assisted description suggestion) is built as an offline stub and is **opt-in** (`--suggest`); the default run and the golden file are unchanged. | On by default; skip A-001 | The brief asks for a safe AI path; opt-in keeps the reviewed golden output stable and the default run purely deterministic. | Users must pass a flag to see suggestions. |
| 21 | extra | AI confidence is clamped twice: in `guardrails.validate_response` and in `scoring.make_candidate` (can only lower the policy value). | Clamp once | Defence in depth; scoring is the single policy place. The second clamp is not independently testable (mutation survives by design). | Slight redundancy. |
| 22 | extra | `apply-decisions` builds an append-only audit log from a review file + decisions file. Approve/reject/investigate record intent only (`change_applied` is always false). Bad or unknown decisions are listed under `errors`; the rest are still recorded; exit stays 0. Multiple decisions on one finding are all kept, in file order. Timestamp is a parameter (default now, UTC) so output is reproducible. | Fail the whole run on any bad decision; keep only the latest decision | A steward's batch should not be lost because of one typo; history matters for audit. | The caller must read `errors`; stderr prints a count. |
| 23 | extra | Quality gates added after review of DISCUSSION_NOTES: 95% coverage floor (`pyproject.toml`), `.github/CODEOWNERS` for red-zone paths, and a secret scan implemented as a pytest test. | Edit `ci.yml` for a scan step and Makefile for the floor | `ci.yml` is red-zone (human edits only), and the pytest scan runs in CI with no workflow change. | CODEOWNERS only takes effect once the repo is on GitHub with branch protection that requires code-owner review; that setting is the human's. |
| 24 | extra | AI suggester eval: 12 hand-labelled cases in `data/eval/suggester_cases.json` (3 adversarial) and a gate in config (`ai_eval_min_accuracy` 1.0, `ai_eval_max_false_suggestions` 0). It runs in pytest and via `python -m dq eval-suggester`. | Eval only in docs; a larger set | The notes claimed an eval set existed; building it makes the claim true and gates changes to the abbreviation list or a future prompt. | The cases are mine, not steward-labelled, so they test the harness and the stub, not a model's real accuracy. A real provider needs a bigger, steward-labelled set and a lower, tuned accuracy bar. |
| 25 | extra | Rows are sent to the suggester only if complete (no R-001 finding), well-formed, and free of email, URL or international-phone text in any allowlisted field. `build_prompt` frames record text as escaped JSON inside a `<record_data>` block, with a system line that calls it untrusted data. | Send everything with an allowlist only; trust a provider-side filter | Cheap tripwires that make the written answer true; the prompt builder is the seam a real provider will use. | The screen is a tripwire, not DLP: national-format phone numbers and names are not caught. `build_prompt` is tested but not yet used by the offline stub. |
| 26 | extra | `.claude/hooks/guard.py` fails open on Windows absolute paths (it strips the working directory with "/" only, so "C:\proj\CLAUDE.md" matches nothing). Found while checking discussion topic 4. Documented with 5 strict-xfail tests in `tests/unit/test_guard_hook.py`; the patch must be applied by a human (red-zone). | Edit the hook myself; ignore | The file is red-zone by the project's own policy. | Until patched, red-zone protection on Windows rests on the `deny` rules in `.claude/settings.json` (not verified) and on review. |
