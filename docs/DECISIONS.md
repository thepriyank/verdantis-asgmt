# Decisions & assumptions

Time is minutes into the 2 h box. Kickoff ran at about T=20.

| # | Time | Decision / assumption | Options considered | Why | Trade-off |
|---|------|-----------------------|--------------------|-----|-----------|
| 0 | 20 | **2 h box**: 20 min already spent, 90 min agent work, last 10 min for the human's final look + share. **One commit per slice straight to `main`**, no branch/PR flow. | 3 h box + PR per slice (CLAUDE.md §0/§9) | The real box is 2 h. The PR round-trip costs ~3 min per slice. | Less review ceremony; `make check` green is still required before every commit. CLAUDE.md conflict noted; the human edits CLAUDE.md (red zone). |
| 1 | 20 | Input = JSON array (Must). CSV = Could. | JSON + CSV both Must | The brief accepts "JSON, CSV, or another"; one format proves the pipeline. | CSV users must convert first. |
| 2 | 20 | Required fields: `item_id`, `item_description`, `unit_of_measure`, `source_system`. Optional: `manufacturer`, `manufacturer_part_number`, `category`. A missing required field → R-001: **high** if `item_id` is missing, else **medium**. | All 7 fields required; only `item_id` required | A steward can't use a record without an id, a description, a UoM or a provenance. The other fields have their own checks. | Missing category is never flagged on its own. |
| 3 | 20 | Output = `{summary, candidates, parse_issues}`. Each candidate is a superset of the brief's example fields. | Bare list as in the brief | The summary and parse issues help the steward triage; the brief allows the shape to differ. | Consumers expecting a bare list must read `.candidates`. |
| 4 | 20 | The brief's `ai_or_heuristic_candidate` source is split into `heuristic` and `ai_assisted_candidate`. | Keep the combined label | The brief asks to make clear whether a finding came from a rule, a heuristic or AI. | None. |
| 5 | 20 | A repeated `item_id` (any system) → R-003: **high** if the other fields conflict, **medium** if the rows are identical copies. One candidate per row, cross-referencing the others. | Only within one source_system | The brief lists "duplicate item_id" and "conflicting source-system values" as edge cases. | Systems that legitimately share an id namespace will produce noise. |
| 6 | 20 | Same item across systems (H-002) = same canonical manufacturer (trim + casefold) + same canonical MPN on different rows. Description similarity is a Could. | Fuzzy description matching | MPN equality is high-precision and explainable. | Misses duplicates that lack an MPN. |
| 7 | 20 | Allowed UoM list lives in `config/rules.json`: EA, PC, SET, PR, BOX, PK, RL, KG, G, L, ML, M, MM, CM, IN, FT. A known alias (e.g. "each", "pcs", lowercase code) → **low** + `suggested_value`. Unknown → **medium**. | Free-form UoM | ISO/SAP-style short codes are the norm in item masters. | The list is a starting point and needs a steward's sign-off. |
| 8 | 20 | "Vague" description = no digit- or attribute-bearing token, and either ≤ 2 tokens or only generic nouns. | Length-only rule | "bearing" and "valve" (from the brief) fire; "SKF Bearing 6205 ZZ" does not. | Long but meaningless text can slip through. |
| 9 | 20 | Category mismatch: keyword → expected category map in `config/category_keywords.json`. Fires only when a keyword matches, the category is present and differs (casefolded). Confidence 0.70, matching the brief example. | Embedding / AI classification | Deterministic and explainable; the evidence names the keyword. | Limited vocabulary; English only. |
| 10 | 20 | Missing = `None`, `""`, whitespace, `"null"`, `"n/a"`, `"na"`, `"-"` (case-insensitive). Raw values are kept as evidence. | Only None/"" | The brief calls out blanks with whitespace and nulls. | A literal part called "NA" would read as missing (unlikely). |
| 11 | 20 | Numeric `item_id` is accepted as a string. A list/dict field value, or a non-object row, → parse_issue + R-001 high. | Reject the whole file | Bad rows must never crash the run (CLAUDE.md §7). | None. |
| 12 | 20 | `[]` → empty candidates, a message, exit 0. Unreadable file / invalid JSON / non-array top level → stderr error, exit 2. | Exit 1 on empty | Empty is a valid upload, not an error. | None. |
| 13 | 20 | Non-English / abbreviation-heavy text: Unicode-safe tokenising, no translation or abbreviation expansion. | Abbreviation map (BRG → bearing) | Time box. | Known limitation; vague/category heuristics may miss these. |
| 14 | 20 | `finding_id` = first 12 hex characters of sha256(`rule_id|source_system|row_index|item_id`). | UUID4 | Must be stable across runs for the golden test + audit. | Changes if row order changes. |
| 15 | 20 | Severity and confidence are set only in `dq/scoring.py`, from config. Checks return the raw signal. | Each check sets its own | One policy place, easy to audit and tune. | One extra indirection. |
| 16 | 20 | `make` is assumed to run under Git Bash on Windows (it uses `mkdir -p`/`cat`). Fallback: `uv run python -m dq review …` in the README. | Rewrite the Makefile for cmd | The Makefile already exists and works in CI (Linux). | Windows users without Git Bash use the fallback. |
